# 다정한 건강수첩

가족 구성원별 건강정보, 건강기록, 병원 방문·복약 일정을 정리하는 웹앱입니다. 의료 진단·치료 앱이 아니며, 서버 계정이나 기기 간 동기화 없이 현재 브라우저의 `localStorage`를 사용합니다.

## 최종 구현 기능

- 가족 구성원 등록·수정·삭제 및 구성원별 건강정보 조회
- 건강기록 추가·조회·삭제
- 병원 방문·복약 일정 추가·조회·삭제
- 이 기기용 보호자 프로필 및 잠금 해제: 보호자 이름 설정, PIN 잠금 해제, 로그아웃, 지금 잠금, 자동 잠금, 현재 PIN 확인 후 PIN 변경
- PIN 분실 시 두 단계 확인 후 건강 데이터·PIN·보호자 프로필을 삭제하는 초기화. 이후 새 프로필을 설정하고, 보유한 백업은 사용자가 직접 복원
- 일반 JSON 백업·복원 및 별도 비밀번호 보호 암호화 JSON 백업·복원

정상적인 프로필·잠금 사용 및 PIN 변경은 가족 건강 데이터를 지우지 않습니다. **PIN 분실 초기화만은 예외로, 저장된 건강 데이터를 삭제합니다.**

## 실행 방법 및 파일 구조

제출 기준 앱은 `index.html`입니다. 프로젝트 폴더에서 정적 서버를 실행하세요.

```bash
python -m http.server 8000
```

Windows에서 `python` 명령을 사용할 수 없다면 `py -m http.server 8000`을 시도하세요. 브라우저에서 [http://localhost:8000](http://localhost:8000)을 엽니다. PIN과 암호화 백업에는 최신 브라우저의 Web Crypto API가 필요하므로 `localhost` 실행을 권장합니다. 서버는 정적 파일만 제공하며 앱 데이터를 서버에 저장하지 않습니다.

`index.html`에서 직접 연결하는 파일:

- 스타일: `styles.css`, `pin-lock.css`, `backup.css`
- 스크립트: `pin-lock.js`, `backup-ui.js`

동적으로 불러오는 파일:

- 잠금 해제 후 `pin-lock.js`가 `app.js`를 불러옵니다.
- 백업·복원 창을 처음 열 때 `backup-ui.js`가 `backup.js`를 불러옵니다.

따라서 위 파일은 모두 `index.html`과 같은 폴더에 있어야 합니다. `다정한-건강수첩.html`은 이전 단일 파일 버전으로, 현재 `index.html`의 보호자 프로필·잠금과 최신 백업 기능에 동기화되지 않았습니다.

## 이 기기용 보호자 프로필 및 잠금 해제

화면과 기능은 **이 기기용 보호자 프로필 및 잠금 해제**입니다. 실제 서버 계정 로그인, 신원 인증, 서버 복구, 여러 기기 동기화가 아닙니다. 보호자 이름은 이 기기의 프로필을 구분하고 잠금 해제 시 확인하는 표시이며 비밀 정보가 아닙니다.

- 최초 설정 시 보호자 이름과 새 4자리 PIN을 설정하고 PIN을 다시 입력합니다.
- 기존 PIN이 있는 경우, 기존 PIN을 확인한 뒤 보호자 이름을 등록합니다. 기존 PIN 및 가족·기록·일정 데이터는 유지됩니다.
- **로그아웃**과 **지금 잠금**은 앱 화면을 잠금 화면으로 돌립니다. 새로고침 후에도 잠금 해제가 필요합니다.
- 자동 잠금 기본 시간은 5분이며, 보호자 설정에서 1·5·10·15분 중 선택할 수 있습니다.
- PIN 변경은 현재 PIN 확인과 새 PIN 2회 입력이 필요합니다.
- PIN 원문은 저장하지 않습니다. PBKDF2-SHA-256 해시와 임의 솔트는 `dajeong-family-health-pin-v1`, 보호자 이름과 자동 잠금 시간은 `dajeong-family-health-guardian-v1`에 별도로 저장됩니다.

### PIN을 잊었을 때

현재 앱에는 서버 복구 기능이 없습니다. **PIN을 잊었을 때 건강 데이터를 유지하면서 안전하게 복구하는 기능은 제공하지 않습니다.** PIN만 초기화해 기존 데이터를 그대로 표시하는 기능도 없습니다.

잠금 화면에서 PIN 분실 초기화를 선택한 뒤 첫 경고를 확인하고, 두 번째 단계에서 정확히 `데이터 삭제`를 입력해야 초기화됩니다. 이 과정은 현재 브라우저에 저장된 건강 데이터, PIN, 보호자 프로필 설정을 삭제합니다. 백업이 없으면 복구할 수 없습니다. 초기화 후 새 프로필과 PIN을 설정하고, 백업 파일이 있다면 사용자가 직접 복원하세요. 실제 데이터가 있는 브라우저에서는 초기화를 시험하지 마세요.

## 건강 데이터 및 기존 데이터 호환

가족 구성원·기록·일정은 기존 저장 키 `dajeong-family-health-v1`과 데이터 형식을 사용합니다. PIN과 보호자 프로필은 별도 키에 저장됩니다. 정상적인 업그레이드 과정에서 가족 데이터는 초기화되지 않습니다.

가족 구성원 삭제를 확정하면 연결된 건강기록과 일정도 함께 삭제됩니다. 삭제 확인을 취소하면 데이터는 삭제되지 않습니다. 이름이 비어 있거나 정규화 후 중복되는 구성원의 등록은 거부됩니다.

## 일반 JSON 백업·복원

1. `index.html`에서 보호자 프로필과 PIN으로 잠금을 해제합니다.
2. 상단의 **백업·복원**을 엽니다.
3. **일반 JSON 백업 다운로드**를 선택해 가족 구성원·건강기록·병원·복약 일정 데이터를 저장합니다.
4. **JSON 백업 파일 복원**으로 파일을 선택합니다. 파일 검증 후 데이터 교체 확인창이 표시됩니다.
5. 확인창에서 승인한 경우에만 데이터가 백업 내용으로 대체되고 페이지가 새로고침됩니다. 취소, 잘못된 파일, 손상된 파일, 지원하지 않는 파일은 기존 데이터를 바꾸지 않습니다.

복원은 병합이 아니라 가족 구성원·기록·일정 전체 교체입니다. 일반 JSON 백업은 **암호화되지 않아 파일을 열면 건강정보를 읽을 수 있습니다.** 안전한 개인 저장 공간에 보관하세요.

## 비밀번호 보호 JSON 백업·복원

암호화 백업은 Web Crypto API의 PBKDF2-SHA-256(600,000회) 및 AES-GCM을 사용합니다.

### 암호화 백업 만들기

1. **백업·복원 → 비밀번호 보호 백업 만들기**를 선택합니다.
2. 12자 이상의 백업 비밀번호를 입력하고 확인합니다.
3. **암호화 파일 다운로드**를 선택합니다.

암호화 JSON에는 가족 구성원·건강기록·일정 데이터만 포함되며 PIN과 보호자 프로필은 포함되지 않습니다. 백업 비밀번호는 앱에 저장하지 않습니다. 비밀번호를 잊으면 해당 파일은 복원할 수 없으므로, 강하고 고유한 비밀번호를 사용하고 파일과 별도로 안전하게 보관하세요.

### 암호화 백업 복원

1. **JSON 백업 파일 복원**에서 암호화 JSON 파일을 선택합니다.
2. 파일을 만들 때 사용한 백업 비밀번호를 입력합니다.
3. 복호화와 내용 검증이 성공한 뒤 표시되는 확인창에서 승인해야 데이터가 교체됩니다.

잘못된 비밀번호, 손상된 파일, 지원하지 않는 형식은 데이터 저장 전에 거부됩니다. 복원 확인을 취소해도 기존 데이터는 유지됩니다. 복원은 전체 교체이며 PIN과 보호자 프로필은 백업 대상이 아니므로 복원 후에도 그대로 유지됩니다.

## localStorage 및 보안상 주의사항

- 이 앱은 실제 서버 계정 로그인, 계정 복구, 서버 데이터베이스·권한 관리, 기기 간 동기화를 제공하지 않습니다.
- 건강 데이터는 `localStorage`에 JSON으로 저장되며 **저장 데이터 자체는 암호화되지 않습니다.** PIN 잠금과 자동 잠금은 화면 접근을 제한할 뿐, 브라우저 저장 공간이나 개발자 도구에 접근할 수 있는 사람을 막는 보안 경계가 아닙니다.
- 암호화 백업은 내려받은 파일을 보호하지만 앱의 `localStorage`를 암호화하지 않고, 기기나 실행 중인 브라우저의 보안 문제도 해결하지 않습니다.
- 일반 JSON 백업은 평문입니다. 암호화 백업도 비밀번호를 잊으면 복구할 수 없습니다.
- 브라우저 저장 데이터 삭제, 저장 공간 문제, 기기 손실에 대비해 백업을 별도의 안전한 곳에 보관하세요. 공용 기기에 민감한 정보를 입력하지 말고 기기 자체의 화면 잠금도 사용하세요.

## 수동 테스트 방법

삭제해도 되는 테스트 데이터나 별도 브라우저 프로필을 사용하세요. PIN 분실 초기화는 건강 데이터 전체를 삭제할 수 있으므로 실제 데이터를 가진 프로필에서 시험하지 마세요.

1. 보호자 이름과 PIN을 설정합니다. PIN 재입력 불일치와 잘못된 이름·PIN이 거부되는지 확인하고, 새로고침 후 올바른 정보로 잠금 해제합니다.
2. 로그아웃과 지금 잠금을 각각 확인합니다. 자동 잠금을 1분으로 설정해 유휴 후 잠기는지 확인하고, 현재 PIN 확인 후 PIN을 변경해 새 PIN으로 잠금 해제합니다.
3. 가족 구성원을 등록·수정·삭제하고 건강기록·병원 방문·복약 일정을 추가·조회·삭제합니다. 새로고침 후 데이터가 유지되는지 확인합니다.
4. 일반 JSON을 내려받아 복원합니다. 잘못된 JSON과 복원 확인 취소에서 기존 데이터가 유지되는지 확인합니다.
5. 비밀번호 보호 백업에서 12자 미만 비밀번호와 서로 다른 확인 비밀번호가 거부되는지 확인합니다. 유효한 비밀번호로 백업을 만든 후 파일에서 건강정보가 평문으로 보이지 않고 PIN·보호자 프로필이 포함되지 않는지 확인합니다.
6. 암호화 백업 복원에서 잘못된 비밀번호, 손상 파일, 지원하지 않는 파일을 시험해 데이터가 유지되는지 확인합니다. 올바른 비밀번호 후 복원을 취소해도 유지되는지, 승인하면 백업 시점 데이터로 교체되는지 확인합니다.
7. 복원 후 PIN과 보호자 프로필이 유지되고 기존 가족·기록·일정 기능이 계속 동작하는지 확인합니다.
8. PIN 분실 초기화는 별도 테스트 프로필에서만 진행합니다. 첫 경고 취소와 두 번째 확인 취소 시 데이터가 유지되는지, 두 단계를 완료하면 데이터 삭제 후 새 프로필 설정을 요구하는지 확인합니다. 백업이 있다면 직접 복원합니다.

## 사용자 보고 실제 브라우저 테스트 결과

다음은 사용자가 직접 브라우저에서 확인했다고 보고한 결과입니다. 이번 문서 검수에서 브라우저 테스트를 새로 수행한 것은 아닙니다.

### 1차 보호자 프로필·잠금 및 기존 기능

사용자는 보호자 이름·PIN 설정, PIN 불일치 거부, 올바른 정보로 잠금 해제, 잘못된 정보 거부, 로그아웃, 지금 잠금, 자동 잠금, 현재 PIN 확인 후 PIN 변경, PIN 분실 초기화를 확인했으며 문제를 발견하지 못했다고 보고했습니다. 초기화는 취소 시 데이터가 유지되고 확인 문구 완료 후 테스트 데이터가 삭제되어 새 PIN 설정 화면이 표시됐다고 보고했습니다. 가족 구성원 등록·수정·삭제, 건강기록 및 병원·복약 일정 추가·조회·삭제, 일반 JSON 백업·복원, 잘못된 JSON·복원 취소 후 데이터 유지, 새로고침 후 데이터와 PIN 상태 유지도 정상 작동했다고 보고했습니다.

### 2차 암호화 백업·복원

사용자는 일반 JSON 백업·복원, 비밀번호 길이 검사·불일치 차단, 암호화 파일 생성, 잘못된 비밀번호·손상 파일 거부, 복원 취소, 올바른 비밀번호와 승인 후 복원을 확인했고 문제가 없었다고 보고했습니다. 암호화 파일에서 건강정보가 평문으로 보이지 않고 PIN·보호자 프로필이 포함되지 않으며, 복원 후 PIN·프로필과 기존 가족·건강기록·일정 기능이 유지됐다고 보고했습니다.

위 결과는 사용자 보고이며, 이 최종 검수에서 새 브라우저 테스트를 수행한 것이 아닙니다.

## 최종 정적 검수와 배포

파일 목록과 소스 내용을 확인했습니다. `index.html`에서 필요한 CSS와 잠금·백업 UI 스크립트를 직접 연결하고, 잠금 해제 후 `app.js`, 백업 기능 실행 시 `backup.js`가 동적으로 불리는 구성을 확인했습니다. 가족·기록·일정 처리와 기존 PIN·보호자 프로필, 일반·암호화 백업 코드 및 문서의 핵심 설명을 검토했습니다. 이는 정적 소스 검토이지 브라우저 실행 검증은 아닙니다.

이번 검수에서는 코드 기능을 수정하지 않았고 배포하지 않았습니다.
