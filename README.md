# 다정한 건강수첩

가족 구성원별 건강정보·건강 기록·병원 방문 및 복약 일정을 정리하는 웹앱입니다. 의료 진단·치료 앱이 아니며, 로그인이나 앱 서버 없이 브라우저의 `localStorage`를 사용합니다.

## PIN 잠금이 적용된 앱 실행

PIN 잠금은 분리형 앱인 `index.html`에 적용되어 있습니다. PIN 잠금이 필요한 경우 **`index.html`을 실행하고 `다정한-건강수첩.html`은 열지 마세요.** 단일 파일은 이번 PIN/백업 변경과 동기화되지 않은 기존 버전입니다.

프로젝트 폴더에서 정적 서버를 실행하세요.

```bash
python -m http.server 8000
```

Windows에서는 `py -m http.server 8000`을 사용할 수 있습니다. 브라우저에서 [http://localhost:8000](http://localhost:8000)을 여세요. `index.html`, `styles.css`, `app.js`, `pin-lock.js`, `pin-lock.css`, `backup-ui.js`, `backup.js`, `backup.css` 파일이 모두 같은 폴더에 있어야 합니다. 서버는 정적 파일만 제공하고 앱 데이터를 서버로 전송하지 않습니다. 최신 브라우저의 Web Crypto API가 필요합니다.

## PIN 동작 및 저장

- 처음 열면 4자리 숫자 PIN을 설정하고 재입력합니다. 이후 페이지를 열 때마다 PIN 입력이 필요합니다.
- 앱 화면 상단의 **지금 잠금** 버튼을 누르면 잠금 화면으로 돌아갑니다.
- 앱 기능 코드는 올바른 PIN을 입력한 뒤에만 불러옵니다.
- PIN 원문은 저장하지 않습니다. Web Crypto의 PBKDF2-SHA-256(600,000회)과 임의 솔트로 처리합니다. PIN 설정 키 `dajeong-family-health-pin-v1`에는 버전, 알고리즘, 반복 횟수, 솔트, 해시만 저장됩니다.
- PIN을 잊으면 복구할 수 없습니다. 해당 브라우저의 `localStorage`에서 **PIN 설정 키 `dajeong-family-health-pin-v1`만** 지우고 페이지를 새로고침하면 새 PIN을 설정할 수 있습니다. 건강정보 키 `dajeong-family-health-v1`은 지우지 마세요.

**보안 한계:** PIN은 앱 화면 접근을 막는 잠금이지, 건강정보 자체의 암호화가 아닙니다. 건강 데이터는 `dajeong-family-health-v1` 키에 JSON으로 저장됩니다. 개발자 도구나 브라우저 저장 공간에 접근할 수 있는 사람은 PIN을 우회해 데이터를 볼 수 있습니다. PIN도 4자리이므로 운영체제 계정 잠금과 기기 보안을 대신하지 않습니다. 공용 기기에 민감한 건강정보를 저장하지 마세요.

## 기존 기능

PIN 확인 뒤 기존 기능을 그대로 사용합니다.

- 가족 구성원 등록·수정·삭제 및 구성원별 건강정보 조회
- 건강 기록 추가·조회·삭제
- 병원 방문·복약 일정 추가·조회·삭제
- 기존 `localStorage` 건강정보 유지
- 반응형 모바일·태블릿·데스크톱 디자인
- 빈 이름·중복 이름 방지 및 삭제 취소 처리

가족 구성원 삭제 시 연결된 건강 기록과 일정도 함께 삭제됩니다. 의료 진단·치료나 복약 지시를 제공하지 않습니다. 치료·복약 판단은 의료진·약사에게 상담하고 응급 상황에는 119 또는 현지 응급서비스를 이용하세요.

## 백업·복원 사용법

1. `index.html`을 열고 PIN을 입력해 앱을 잠금 해제합니다.
2. 상단의 **백업·복원** 버튼을 누릅니다.
3. **JSON 백업 다운로드**를 눌러 `dajeong-health-backup-날짜.json` 파일을 저장합니다. 파일에는 가족 구성원, 건강기록, 병원·복약 일정이 들어갑니다. PIN 설정은 포함되지 않습니다.
4. 복원이 필요하면 **JSON 파일 복원**을 눌러 이 앱에서 만든 JSON 백업 파일을 선택합니다. 앱이 만든 백업 형식·버전만 지원합니다.
5. 파일 크기, 형식, 필수 데이터 목록, 각 항목의 값과 가족 구성원 연결을 검증합니다. 손상되었거나 형식이 다른 파일은 복원하지 않으며, 검증이 끝나기 전에는 현재 데이터를 쓰거나 삭제하지 않습니다.
6. 유효한 파일이면 복원 대상 항목 수와 함께 **현재 데이터가 백업 내용으로 대체된다**는 확인창이 표시됩니다. 확인을 취소하면 기존 데이터는 변경되지 않습니다. 승인하면 구성원·기록·일정 전체를 선택한 백업으로 대체한 뒤 페이지를 새로고침합니다. PIN 설정은 유지됩니다.

**중요:** 복원은 병합이 아니라 교체입니다. 필요하면 현재 데이터도 먼저 백업하세요. JSON 백업은 암호화되지 않은 민감한 건강정보 파일이므로 공유·공용 기기에 저장하지 말고 안전한 개인 저장 공간에 보관하세요. 파일 크기는 최대 10MB이며 각 데이터 목록은 최대 10,000개까지 지원합니다. 파일을 읽을 수 없거나 확인창에서 취소하면 복원하지 않습니다. 저장 공간 문제로 복원 데이터를 저장할 수 없는 경우 오류를 알리고 기존 데이터를 보존하도록 처리합니다.

## 브라우저 테스트 결과 기록

사용자가 실제 브라우저에서 이번 버전을 직접 테스트한 결과를 기록합니다. **PIN 기능, 가족 구성원, 건강기록, 일정, JSON 백업·복원이 정상 작동했고, 복원 확인 취소와 잘못된 파일 처리 후에도 기존 데이터가 유지되었으며 복원 후 PIN도 정상 작동했습니다.** 테스트 날짜·브라우저 정보는 제공되지 않았습니다. 이 기록은 사용자가 보고한 테스트 결과이며, 이번 README 변경 작업에서 별도의 브라우저 테스트를 수행한 것은 아닙니다.

## 수동 테스트 방법

실제 가족 정보 대신 테스트 정보를 사용하세요. 아래 절차는 기능을 다시 확인하거나 회귀 테스트할 때 사용할 수 있습니다.

### PIN과 기존 기능 확인

1. 프로젝트 폴더에서 `python -m http.server 8000`을 실행하고 [http://localhost:8000](http://localhost:8000)을 엽니다. Windows에서는 `py -m http.server 8000`을 시도하세요.
2. 아직 PIN이 없다면 4자리 숫자를 두 번 입력해 설정합니다. 새로고침 후 PIN 화면이 나타나는지 확인합니다. 잘못된 PIN으로는 잠금이 유지되고 올바른 PIN으로 해제되는지 확인합니다.
3. 상단 **지금 잠금**을 눌러 잠금 화면으로 돌아가는지 확인하고, PIN을 다시 입력해 앱을 엽니다.
4. 테스트 가족 구성원을 등록하고 상세 화면에 나타나는지 확인합니다. **수정**으로 이름이나 정보를 바꿔 저장하고 변경 내용이 반영되는지 확인합니다.
5. 건강기록을 추가·조회하고 삭제를 시도합니다. 삭제 확인창에서 취소했을 때 유지되는지, 별도 테스트 기록의 삭제를 확정했을 때 사라지는지 확인합니다.
6. 병원 방문 일정과 복약 일정을 추가·조회합니다. 각각의 삭제 취소와 삭제 확정도 확인합니다. 구성원 삭제는 확인창에서 취소한 뒤 유지되는지 확인하고, 별도의 테스트 구성원은 삭제를 확정해 연결 데이터까지 제거되는지 확인합니다.

### 백업·복원 안전성 확인

1. 테스트 구성원 1명, 건강기록 1건, 병원·복약 일정 1건을 만들고 **백업·복원 → JSON 백업 다운로드**를 실행합니다. 다운로드한 `.json` 파일이 존재하고 세 종류 데이터가 들어 있는지 텍스트 편집기로 확인합니다. 백업에 PIN 설정 데이터가 포함되지 않아야 합니다.
2. 앱에 별도 테스트 데이터를 더해 백업 시점과 다른 상태로 만든 뒤, **JSON 파일 복원**에서 유효한 파일을 선택합니다. 확인창에서 **취소**하고 새로고침해 현재 데이터가 유지되는지 확인합니다.
3. 같은 파일을 다시 선택하고 확인창에서 승인합니다. 새로고침 후 백업 시점의 구성원·기록·일정으로 교체되었는지 확인합니다. PIN 화면이 먼저 나타나고 기존 PIN으로 잠금 해제되는지도 확인합니다.
4. 테스트 데이터를 현재 상태에 추가한 뒤, 형식이 다른 파일(`{}`), 문법이 깨진 JSON, 앱 백업에서 항목을 일부 지우거나 날짜·구성원 연결을 잘못 바꾼 JSON을 각각 선택합니다. 오류 안내 후 새로고침해 기존 데이터가 그대로인지 확인합니다.
5. 10MB를 넘는 파일도 거부되는지 확인합니다. 파일을 선택하지 않거나 복원 확인창에서 취소한 경우에도 현재 데이터가 바뀌지 않아야 합니다.

## 파일 및 변경 범위

- `index.html`, `styles.css`, `app.js` — 기존 분리형 건강수첩과 가족·기록·일정 기능
- `pin-lock.js`, `pin-lock.css` — 기존 분리형 앱의 PIN 잠금
- `backup-ui.js`, `backup.css` — 백업·복원 버튼과 대화상자 UI
- `backup.js` — JSON 백업 다운로드, 가져오기 파일 검증, 확인창, 복원 및 저장 오류 처리
- `README.md` — 실행 및 PIN, 백업·복원, 수동 테스트 안내와 사용자 보고 브라우저 테스트 결과
- `다정한-건강수첩.html` — 기존 단일 파일 버전. 이번 변경에 포함되지 않아 PIN/백업 기능이 적용되지 않았습니다.

데이터는 현재 브라우저에 저장되며 다른 기기와 동기화되지 않습니다. 브라우저 저장 데이터를 삭제하면 백업이 없는 기록은 복구할 수 없습니다.

## 의료 안내

이 앱은 가족 건강기록·일정 정리 도구이며 증상 진단, 치료 권고, 복약 지시를 제공하지 않습니다. 의료진의 진료나 응급서비스를 대신하지 않습니다. 복약은 의료진·약사의 안내를 따르고 응급 상황에는 119 또는 현지 응급서비스에 연락하세요.

## 반응형 화면 수동 점검

브라우저 개발자 도구의 반응형 모드 또는 실제 휴대전화에서 320px, 375px, 390px, 430px 화면 폭을 확인합니다. PIN 화면, 가족 목록, 건강정보 카드, 백업·복원 창과 기록·일정 입력폼에 가로 스크롤이나 겹침이 없는지 살펴봅니다.

## 보안 및 복구 한계

분리형 앱에는 서버 저장, 기기 간 동기화, 건강 데이터 암호화, PIN 분실 복구 기능이 없습니다. PIN은 화면 접근을 제한할 뿐이고, JSON 백업 파일도 암호화되지 않습니다. 백업 파일을 안전하게 보관하세요.
